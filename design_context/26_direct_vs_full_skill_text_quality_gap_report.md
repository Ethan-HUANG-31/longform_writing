# Direct Write 与 Full Skill Write 文本质量差异分析

## 1. 结论摘要

在 Phase D0.5 的盲评中，`direct write` 在 `case_05` 和 `case_10` 的真实文本质量上胜过 `full skill write`；`full skill write` 在 `case_07` 胜出，主要原因是它完成了更复杂的长程结构要求。

这说明当前结论不是“direct write 全面优于 full skill write”，而是：

- `full skill write` 更擅长需求覆盖、章节连续、线索闭环和结构完整。
- `direct write` 更擅长自然场景流动、情绪转折、对话节奏和最终阅读体验。
- 当前 `full skill write` 的主要问题不是工程流程，而是读者可感知的文本质量问题：重复、程序化、解释性强、情绪不够自然。

因此，下一版 V1 的目标不应是继续证明 full skill 在工程上更完整，而应是：

> 保留 full skill 的长程控制能力，同时通过 chapter review / revision loop 修复机械化文本问题，吸收 direct write 的自然场景感和人物压力表达。

## 2. 样本范围

本文档基于 D0.5 盲评中最有区分度的三个样本：

| Case | Direct Write 表现 | Full Skill Write 表现 | 结论 |
|---|---|---|---|
| `case_05` 单主角责任揭示 | 胜出 | 第二 | Direct 更像完整短篇，责任转折更自然 |
| `case_07` 双时间线连续性 | 未胜出 | 胜出 | Full skill 完成四阶段揭示，结构控制更强 |
| `case_10` 图书馆悬疑 | 胜出 | 第二 | Direct 更有人情味和阅读流，full skill 更像线索清单 |

## 3. 差异一：Full Skill 能保住结构，但容易暴露“执行步骤感”

### 问题说明

`full skill write` 的优势来自中间工程表示：summary、beats、codex、previous summaries、text_before 等。这使它更容易按计划完成章节目标。

但副作用是，正文有时会保留“正在执行 beat”的痕迹。读者读到的不是自然推进的场景，而是一个角色反复检查、记录、对齐、确认线索。

### Evidence A：case_05 full skill 的开篇重复检查

来源：`runs/integrated_05_v2/manuscript/final.md`

```text
17: 他将报告平放在膝盖上，手指沿着撕扯边缘触摸。纤维的毛刺扎进指纹，切口呈直线，像是被刀片裁切过的。
25: 小帅将报告举到灯光下，纸张半透明，背面的文字隐约可见。他放下报告，手指沿着纸张边缘滑动，感受纤维的毛刺。
31: 小帅将报告翻过来，背面同样没有封面残留的痕迹。他再次触摸第一页的上边缘，指尖沿着切口滑动。纤维的毛刺扎进指纹……
37: 小帅将报告举到灯光下，纸张半透明，背面的文字隐约可见。他放下报告，手指沿着纸张边缘滑动，感受纤维的毛刺。
```

这几处文字都在服务同一个信息：封面被刻意移除。但动作和感官细节重复出现，导致文本像“线索检查流程”，而不是推进中的小说场景。

### Evidence B：case_05 full skill 的便签记录重复

来源：`runs/integrated_05_v2/manuscript/final.md`

```text
53: 小帅从办公桌抽屉里找出一支笔和空白便签纸，在纸上写下：“无封面，项目名称/日期被涂改。”
57: 他拉开办公桌抽屉，找到一支黑色圆珠笔和空白便签纸。笔尖在纸上划过，留下清晰的字迹：“无封面，项目名称/日期被涂改。”
275: 他伸手取出第四张便签纸，写下：“审批页：小美建议暂停（6/15），李工建议重新评估（6/18），小帅批准继续推进（6/20）”……
279: 小帅将第四张便签纸放在第三张右侧。纸边对齐，四张便签纸在镇纸下排成一行。
281: 第一张：“无封面，项目名称/日期被涂改”。第二张：“第三页、第七页、第十二页各一处涂黑数据……”……
```

这里的问题不是“有便签”本身，而是便签反复承担总结功能。正文不断把已经发生的发现重新列出来，削弱了悬疑和情绪的推进。

### 后续优化目标

V1 revision loop 需要加入“机械执行痕迹检查”：

- 同一线索的物理检查动作不能连续重复。
- 同一信息被记录、复述、归纳超过一次时，需要压缩或转化为新的冲突。
- beat-to-prose 阶段不应把 beat checklist 直接显影到正文里。

## 4. 差异二：Direct Write 更容易把线索转成人物责任，而 Full Skill 容易停留在线索证明

### 问题说明

`direct write` 在 `case_05` 胜出，关键不是线索更多，而是线索最终压到人物身上，形成责任感和选择感。

`full skill write` 也完成了线索闭环，但最终更像“证明封面确实属于报告”，人物情绪主要在最后被总结出来。

### Evidence A：case_05 direct write 的责任转折

来源：`baseline_runs/direct_write/05_medium_length_single_protagonist/manuscript.md`

```text
201: 他想了很久，终于想起来了。他说的是：“那就按原计划走吧。”
203: 他没有反对。他甚至没有问“数据不一致的问题怎么解决”。他只是点了点头，说了那句“按原计划走”，然后会议就结束了。
211: 他把风险压在了心里，告诉自己“应该不会出大问题”，然后签了那份报告。
241: 他想起小美三年前拿着文件来找他签字的那天晚上。他头也没抬就签了……
245: 他签了字，却没有看内容。
```

这组证据把“报告缺封面”推进成了“他亲自点头、亲自签字、亲自忽略风险”。线索不只是客观事实，而是人物责任的压力来源。

### Evidence B：case_05 direct write 的结尾动作

来源：`baseline_runs/direct_write/05_medium_length_single_protagonist/manuscript.md`

```text
297: 他一直以为自己只是项目的执行者，不是决策者。
301: 他没有看内容，但签了名。他在会议上没有反对，但点了头。他知道风险存在，但选择了忽略。
327: 他打印了一份，拿在手里，然后走到档案柜前，把那份没有封面的报告拿出来，把打印好的封面放在最上面，用装订机重新装订好。
333: 明天，他会把这份报告交给该交的人。然后他会坐下来，把三年前那个会议上的每一句话、每一个决定、每一个沉默，都写清楚。
351: 但以后，他会看的。
```

这里的结尾不是只说“他明白了责任”，而是让他做了一个具体动作：重新装订封面、准备交出报告、补写沉默。最后一句“但以后，他会看的”把人物缺陷和改变收束到一个非常具体的行为上。

### Evidence C：case_05 full skill 的结尾偏总结

来源：`runs/integrated_05_v2/manuscript/final.md`

```text
291: 纸张展开时发出细微的脆响。封面中央偏上位置，红色粗体字印着“高风险，不建议上线”。
305: 他拿起封面，将右侧边缘对准报告首页的上缘。撕扯痕迹对齐，倾斜角度一致，宽度吻合。
317: 他松开手，封面平整地覆盖在报告首页上。红色文字在台灯下清晰可见……
329: 小帅终于明白，缺失的不是一页封面，而是他一直回避的责任。
```

full skill 的线索证明很完整，但大量篇幅用于确认封面和报告物理吻合。人物的责任感主要在最后一句被点明，缺少 direct write 那种“回忆选择 -> 识别责任 -> 做出行动”的连续压力。

### 后续优化目标

V1 revision loop 需要检查每个关键线索是否完成了三步转化：

```text
事实线索 -> 人物压力 -> 人物选择/行动
```

如果正文停留在“线索被证明是真的”，但没有推动人物做出新选择，就应触发章节重写。

## 5. 差异三：Direct Write 的局部场景更自然，Full Skill 的推理更像清单

### 问题说明

`case_10` 是最能说明问题的样本。`full skill write` 的悬疑结构更规整，线索链也更清楚；但它把推理写成了反复确认和显式列点，导致小说感下降。

`direct write` 的推理不一定每一步都最精巧，但它有对话、有误判、有对抗、有最终的人情落点，因此阅读体验更好。

### Evidence A：case_10 full skill 的整段重复

来源：`runs/integrated_10/manuscript/final.md`

```text
354: 小帅盯着那行字看了几秒，然后从笔记本里取出三张旧借书卡，并排放在名单旁边。蓝色圆珠笔的墨色一致……
356: 小帅将三张借书卡并排放在名单旁边。蓝色圆珠笔的墨色一致……
358: 他拿起第一张借书卡，翻到背面。那条从左上角斜向右下角的浅折痕……
366: 小帅将三张借书卡并排放在名单旁边。蓝色圆珠笔的墨色一致……
368: 他拿起第一张借书卡，翻到背面。那条从左上角斜向右下角的浅折痕……
398: 他将三张借书卡按发现顺序排开，指尖依次点过上面的日期……
410: 他将三张借书卡按发现顺序排开，指尖依次点过上面的日期……
```

这不是普通的强调，而是生成过程中的重复没有被修掉。它会直接破坏读者对悬疑节奏的信任。

### Evidence B：case_10 full skill 的清单式推理

来源：`runs/integrated_10/manuscript/final.md`

```text
378: **一、旧借书卡**——纸质借书卡三年前已淘汰……
380: **二、日期对不上**——2023年5月20日不是借书日期……
382: **三、书号密码**——I247.5/1024、G258.2/2031、G251.5/3320……
386: **排除小美**——她没有钥匙，闭馆后无法进入。
390: 小帅在笔记本底部写下：**前管理员，阿强。**
```

这段逻辑很清楚，但更像侦探笔记或评测答案。作为正文，它把读者应该经历的发现过程提前整理成了清单，牺牲了场景中的犹豫、误解、试探和情绪变化。

### Evidence C：case_10 direct write 的对话推进和误判过程

来源：`baseline_runs/direct_write/10_mystery_clue_fairness_smoke/manuscript.md`

```text
130: “你有没有想过，”小美说，“这些书可能不是读者放错的？”
134: “我是说，有人故意把它们放在那里。”小美压低声音……
146: 小帅觉得这个推理有点道理，但总觉得哪里不对。
150: 《城南旧事》的借书日期是1999年6月15日。而图书馆的借阅记录显示，这本书在2003年、2008年、2015年都曾被正常借出过。
162: “而且你看日期，”小帅把《城南旧事》的借书卡翻过来，“1999年6月15日是星期一。但图书馆每周一闭馆，不对外借书。”
168: “不一定是伪造，但至少不是真实的借阅记录。”小帅说，“有人在用这些借书卡传递某种信息。”
```

这里的推理不是一次性列出，而是在小美的猜测、小帅的怀疑、系统记录和日期矛盾之间推进。读者能跟着人物一起修正判断。

### 后续优化目标

V1 revision loop 应增加“推理戏剧化”要求：

- 推理不要默认写成清单。
- 至少保留一处误判、反驳或重新解释。
- 让对话承担部分推理压力，而不是让叙述者一次性解释完。
- 悬疑类章节需要检查“线索公平性”和“阅读戏剧性”是否同时存在。

## 6. 差异四：Direct Write 更容易给类型 payoff 加上人情落点

### 问题说明

`full skill write` 在 `case_10` 能完成“旧借书卡 -> 日期异常 -> 书号密码 -> 储物柜 -> 阿强”的链条，但它的结尾仍偏程序化：线索被确认，嫌疑人被排除，人物身份被写下。

`direct write` 的结尾把谜底转成了图书馆、捐赠人、前管理员之间的长期遗憾，因此 payoff 更有人味。

### Evidence A：case_10 direct write 的人情动机

来源：`baseline_runs/direct_write/10_mystery_clue_fairness_smoke/manuscript.md`

```text
222: 6月15日的记录栏里，写着：“陈秀兰女士捐赠图书一批，共四十七册。因系统故障，暂未录入，待修复后补登。”
230: 7月3日：“陈秀兰女士因病去世。其家属来电，询问捐赠事宜。告知正在处理。”
250: “我曾多次向馆长反映名单的事，但馆长认为年代久远，捐赠人已无从查证，不予重视……若你能看到这段话，请务必替我将名单公之于众。拜托了。”
260: 名单上第四十七位捐赠人，名字是：陈秀兰。
```

这些信息让谜题不只是“谁放了卡片”，而是“谁被遗忘了、谁试图补救、谁应该被重新记录”。类型 payoff 有了情感重量。

### Evidence B：case_10 direct write 的结尾回收

来源：`baseline_runs/direct_write/10_mystery_clue_fairness_smoke/manuscript.md`

```text
370: “你们说得对。这份名单应该被记录。”
378: “阿强……去年年底去世了。”
392: 王馆长想了想，说：“暂时不用。我想在图书馆里设一个专门的展区，把这些书和借书卡都展示出来……”
396: “而且，”小帅补充道，“也可以让大家知道阿强。他为了这份名单，花了二十多年。”
398: 屏幕上，那些名字一个一个地出现，像是从时间里被打捞上来的碎片，重新拼合成一幅完整的画面。
404: 而那些被错放的书，终于等到了它们真正的读者。
```

这个结尾把“线索解开”转成“名字被记录、阿强被记住、书等到读者”。悬疑 payoff 和主题 payoff 合在了一起。

### Evidence C：case_10 full skill 的结尾停在确认链条

来源：`runs/integrated_10/manuscript/final.md`

```text
388: 他停笔，目光扫过前三行推理。拥有钥匙、知道储物柜存在、熟悉索书号系统、与2023年5月20日有关联——符合所有条件的人只有一个。
390: 小帅在笔记本底部写下：**前管理员，阿强。**
392: 他打开员工档案系统，输入查询。屏幕显示：阿强，2023年6月离职。
394: 小帅合上笔记本，将捐赠名单、三张借书卡、密码记录依次放入文件夹。他站起身，朝主任办公室走去。
```

这段完成了身份确认，但还没有充分展开“为什么这件事值得被解决”。读者知道了答案，却较少感受到答案背后的人的重量。

### 后续优化目标

V1 revision loop 需要检查 genre payoff 的两层完成度：

```text
机制 payoff：谜题、线索、身份是否闭合。
情感 payoff：人物、关系、主题是否因此发生变化。
```

只完成第一层，不应视为高质量通过。

## 7. 差异五：Full Skill 的优势仍然重要，问题是缺少后处理修订

### 问题说明

虽然本文重点分析 direct write 胜出的原因，但不能得出“不要 full skill”的结论。`case_07` 说明，当任务需要严格的多阶段揭示时，full skill 的结构控制明显有价值。

### Evidence：case_07 full skill 完成复杂揭示

来源：`runs/integrated_07_v4/manuscript/final.md`

```text
225: 光标停在红色段落上。小帅看到自己的手在键盘上方的悬停……
229: 光标移动。选中。右键菜单弹出。删除。
231: 红色段落消失。
283: 不是遗忘。不是记忆模糊。是主动删除。
429: 屏幕里，项目经理合上笔记本：“责任认定到此为止。小美，你签一下离职协议。”
431: 小美没有动。她坐在角落里，面前摊开一份文件，封面上印着“离职协议”四个字。
```

这说明 full skill 可以把“过去录像 -> 删除风险提示 -> 小美承担责任”的长程因果链写完整。它的问题不是没有价值，而是初稿需要 revision loop 去修掉重复和机械感。

同一个样本也暴露 full skill 的重复问题：

```text
33: 项目经理转过身，拍了拍手上的白板笔灰。“有问题吗？”
45: 项目经理转过身，拍了拍手上的白板笔灰。“有问题吗？”
185: 小帅松开鼠标，手指在桌面上敲了两下……
187: 小帅松开鼠标，手指在桌面上敲了两下……
```

因此 full skill 的正确迭代方向不是移除工程化结构，而是在结构生成之后加入文本质量修订。

## 8. 沉淀为后续优化目标

基于以上证据，后续 V1 应把以下目标写入 chapter review / revision loop。

### 8.1 去重复

检查同一动作、同一线索、同一句判断是否在相邻段落或同一章节内重复出现。

重点检测：

- 举到灯光下；
- 对齐边缘；
- 并排放置；
- 再次确认字迹；
- 重新列出已有线索；
- 整段推理重复。

### 8.2 去清单化

当正文出现“一、二、三”或显式 checklist 时，判断它是否破坏小说场景。

不是完全禁止角色写笔记，而是要求：

- 笔记必须制造新的判断或行动；
- 不能替代场景冲突；
- 不能把读者应该体验的推理过程压缩成答案。

### 8.3 线索转人物压力

每个关键线索都应回答：

```text
这个线索让人物更难逃避什么？
这个线索迫使人物做了什么选择？
这个选择改变了后续关系或行动吗？
```

如果只有“线索被确认”，没有人物压力，就需要修订。

### 8.4 对话承担冲突

对话不应只解释事实。它至少应该承担一种功能：

- 误判；
- 反驳；
- 试探；
- 回避；
- 压迫；
- 关系变化。

`case_10 direct write` 中小美和小帅共同推理的段落可以作为参考方向。

### 8.5 类型 payoff 需要双层闭合

对悬疑、审判、双时间线等类型故事，评估不能只看“谜题答案是否完整”，还要看：

- 答案是否改变人物；
- 答案是否回应主题；
- 答案是否让前文物件、名字、记忆获得新的意义。

## 9. 对下一版 V1 的验收建议

V1 不应只比较“是否完成任务”，而应比较四个版本：

```text
direct write
simple engineered
full skill unrevised
full skill revised
```

验收目标：

1. `full skill revised` 必须保持 `full skill unrevised` 的长程完整性。
2. `full skill revised` 必须明显减少重复检查、清单式推理和总结式情绪。
3. `full skill revised` 至少在 `case_05` 或 `case_10` 中追平或超过 direct write 的自然阅读体验。
4. 如果 direct write 仍胜出，需要记录它胜出的具体文本机制，继续反哺 revision loop。

最终判断标准不是“工程流程更复杂”，而是：

> 读者是否能在完整长程结构中读到自然、有压力、有回收感的小说。
